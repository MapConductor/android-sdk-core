# geocell 適合ベクタ。android-sdk / ios-sdk / react-sdk で同一のファイル。
#
# ## これは何か
#
# マーカーの空間索引が使う階層セルの名前。3 つの SDK は鍵を Long / Int64 /
# number と別々の型で持つので、数値そのものではなく**文字列で**突き合わせる。
#
# 世界は**正方の 2 セル**（西半球と東半球、一辺 180 度）から始まり、そこから
# 2x2 に細分される。文字列は半球の数字 1 桁のあと、4x4 の細分 1 段ごとに
# 0123456789abcdef の 1 文字が付く。緯度ビットが経度ビットの上。
#
# cordova-plugin-googlemaps の geomodel.js は根が 1 セルで、セルが縦横 2:1 に
# なる。そちらに合わせていたが、幅を分離距離に合わせると高さが 2 倍細かくなり、
# 問い合わせが必要の 2 倍のセルを歩いて 2 倍のマーカーを返していた（東京の
# 街路樹・ズーム 11 で、返した 9,715 件のうち呼び出し側が残したのは 2,156 件）。
# 根を正方 2 枚に割るとその 2 倍が消える。文字列で名前を付けられる性質は残る。
#
# 一致していないと何が起きるか: どのプラットフォームでも地図は描ける。セルの
# 切れ目が違うだけなので、間引いたときに残る木が違う、という形でしか出ない。
# 目で見て気づける差ではないから、ここで止める。
#
# ## 書式
#
#   geocell|緯度|経度|文字数      -> 文字列（半球 1 桁 + 4x4 の文字）
#   level|分離距離(度)            -> 段（応じられなければ none）
#   cell|緯度|経度|段             -> 緯度インデックス,経度インデックス
#   morton|緯度インデックス|経度インデックス|段 -> 鍵（10 進）
#   qlevel|緯度の幅|経度の幅      -> 範囲クエリが歩く段
#   colwalk|west|east|段          -> 開始列,列数
#
# 列は | 区切り。# で始まる行と空行は読み飛ばす。

# 半球だけ。1 文字は西(0)か東(1)かしか言わない。

geocell|0.0|90.0|1
geocell|0.0|-0.0001|1
geocell|0.0|0.0001|1

# 何も起きないまま、広い箱だけが世界の一部しか見なくなる。
